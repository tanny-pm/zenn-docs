VS CodeやIntelliJ IDEAに慣れた開発者がエディタを乗り換えるとき、最初に確認するのは言語サポートの充実度です。補完は効くか、エラーはリアルタイムで表示されるか、フォーマッタは動くか。こうした確認のたびに「拡張を入れろ、言語サーバーを別途インストールしろ」という手順が続くと、乗り換えのモチベーションは削られていきます。

Zedはこの問いに対して独特のアプローチをとっています。主要な言語サーバーをエディタ本体に同梱するという方針です。RustやPythonやTypeScriptは、Zedをインストールした時点でコード補完と診断が動き始めます。別途言語サーバーをセットアップする手間は原則として不要です。

この章では、まずその言語サポートの考え方と仕組みを確認し、補完、ホバー、コードアクションといったコーディング支援機能、診断の表示と活用、フォーマットの設定を見ていきます。後半ではZedの特徴的な機能であるタスク、組み込みターミナル、DAP準拠のデバッガを取り上げ、最後にREPLとJupyterサポートについても触れます。

## 言語サーバーを同梱するという思想

Zedがサポートする言語のうち、Bash、C、C++、CSS、Go、JavaScript、JSON、Markdown、Python、Rust、TypeScript、YAMLをはじめとする主要言語はZed本体に直接組み込まれています。これらは拡張を別途インストールしなくても、該当するファイルを開いた瞬間からシンタックスハイライトとLSP（Language Server Protocol）による支援が有効になります。

言語ごとに細かい事情は異なります。Rustでは、ZedはまずシステムのPATH上に`rust-analyzer`を探し、見つからなければ安定版を自動でダウンロードしてセットアップします。独自ビルドの`rust-analyzer`を使いたい場合は、`settings.json`の`lsp.rust-analyzer`セクションで特定のパスを指定できます。

Pythonでは`basedpyright`が主な言語サーバーとして、Ruffがフォーマッタとリンターとして設定されています。pyright、pylspなど他のサーバーに切り替えることも可能です。また、プロジェクトの仮想環境の中に言語サーバーがインストールされていれば、Zed内蔵のバイナリより優先して使われます。

組み込まれていない言語については、Zedの拡張エコシステムから対応パッケージを追加することで同等の体験を得られます。コミュニティには100以上の言語拡張が公開されています。拡張のインストール方法は第8章で扱います。

## コーディング支援機能

### 補完

言語サーバーが有効な状態でコードを書き始めると、変数名や関数、型、メンバーなどの補完候補がポップアップで表示されます。候補は入力につれてフィルタリングされ、`Tab`キーで確定します。補完ウィンドウが消えたときは`ctrl-space`で手動トリガーできます。補完の自動表示を切りたい場合は`settings.json`で`"show_completions_on_input": false`を指定します。

AIによる複数行補完（Edit Predictions）については第4章で説明しました。LSPによる補完とAI補完は共存しており、入力の文脈に応じてどちらかが候補を出します。

### シグネチャヘルプ

関数の呼び出しを書いて`(`を入力すると、引数リストの型情報とドキュメントがポップアップで表示されます。複数のオーバーロードがある場合は、現在入力している引数の位置に対応するシグネチャがハイライトされます。

### ホバーとコードアクション

シンボルの上にカーソルを合わせると、その型情報やドキュメントコメントがツールチップで表示されます。エラーや警告が出ている箇所ではコードアクション（クイックフィックス）が利用可能で、importの自動追加、変数のリネーム、未使用変数の削除といった操作を適用できます。コードアクションはコマンドパレット（`cmd-shift-p`）から「code actions」と入力して実行するか、エラー行に表示される電球アイコンから呼び出します。

## 診断：エラーを見逃さない

言語サーバーが検出したエラーや警告は、複数の場所で確認できます。

**エディタ内のアンダーライン**が基本の表示です。エラーは赤、警告は黄色のアンダーラインでテキストに重ねて表示され、スクロールバーにも位置が映し出されます。ファイルツリーのパネルでは、問題を含むファイルのアイコンが色分けされるため、どのファイルに問題があるかをひと目で確認できます。

コードの右側にメッセージを直接表示する**インライン診断**（いわゆるError Lens的な表示）はデフォルトでは無効です。有効にするには`settings.json`に以下を追加します：

```jsonc
// settings.json
{
  "diagnostics": {
    "inline": {
      "enabled": true
    }
  }
}
```

診断間の移動には`editor::GoToDiagnostic`（次のエラーへ）と`editor::GoToPreviousDiagnostic`（前のエラーへ）アクションを使います。コマンドパレットから検索するか、キーバインドに割り当てると便利です。

プロジェクト全体の診断をまとめて確認したい場合は、**Project Diagnostics**パネルを使います。`cmd-shift-m`で開くか、コマンドパレットから`diagnostics: deploy`を実行します。このパネルは第5章で紹介したマルチバッファの技術を活用しており、プロジェクト内のすべてのファイルにわたるエラーと警告を1つの画面に並べて表示します。単なるエラー一覧ではなく、各エラーの周辺コードも含めた形で表示されるため、文脈を保ったまま問題を確認できます。さらに、このパネル上でコードを直接編集できるのが大きな特徴で、元のファイルへ移動しなくても修正を加えられます。

大がかりなリファクタリングの後に散らばった型エラーを一気に片付けるといった場面で、このパネルは特に力を発揮します。

![Project Diagnostics パネル。複数ファイルの型エラーが、エラーメッセージと周辺コードとともに1画面に並ぶ](/images/zed-book/ch6-diagnostics-panel.png)
_cmd-shift-m で開く Project Diagnostics パネル。エラー箇所はパネル上で直接編集できる_

## コードのフォーマット

### format on save

保存時の自動フォーマットは`settings.json`で有効にします：

```jsonc
// settings.json
{
  "format_on_save": "on"
}
```

デフォルトでは、言語サーバーが提供するフォーマッタが使われます。

### 外部フォーマッタの指定

PrettierやRuffのような外部ツールをフォーマッタとして使いたい場合は、`formatter`キーに`external`を指定します：

```jsonc
// settings.json
{
  "formatter": {
    "external": {
      "command": "prettier",
      "arguments": ["--stdin-filepath", "{buffer_path}"]
    }
  }
}
```

`{buffer_path}`はZedが現在のファイルパスに自動置換します。

### 言語別の設定

フォーマット設定は言語ごとに個別に指定できます。たとえばTypeScriptはPrettierで、PythonはRuff（言語サーバー経由）でフォーマットするといった使い分けが可能です：

```jsonc
// settings.json
{
  "languages": {
    "TypeScript": {
      "format_on_save": "on",
      "formatter": {
        "external": {
          "command": "prettier",
          "arguments": ["--stdin-filepath", "{buffer_path}"]
        }
      }
    },
    "Python": {
      "format_on_save": "on",
      "formatter": "language_server"
    }
  }
}
```

複数のフォーマッタを直列に実行することも可能で、ESLintによる自動修正とPrettierによるフォーマットを順番にかける構成も組めます。`settings.json`全体の構造や他の設定項目については第8章で詳しく扱います。

## タスクで繰り返しを自動化する

テストの実行、ビルド、デプロイスクリプトの起動。こうした定番コマンドを毎回ターミナルに手で打ち込んでいないでしょうか。ZedのTask機能を使うと、よく使うコマンドをあらかじめ定義しておき、コマンドパレットから素早く呼び出せるようになります。

### tasks.jsonを定義する

タスクの定義ファイルは2か所に置けます：

- `.zed/tasks.json`：そのプロジェクトだけで使えるローカルタスク
- `~/.config/zed/tasks.json`：すべてのプロジェクトで使えるグローバルタスク

ファイルを開くには、コマンドパレットから`zed: open project tasks`（ローカル）または`zed: open tasks`（グローバル）を実行します。定義はJSON配列で、各タスクを1オブジェクトとして記述します：

```jsonc
// .zed/tasks.json
[
  {
    "label": "テストを実行",
    "command": "cargo",
    "args": ["test"],
    "cwd": "$ZED_WORKTREE_ROOT"
  },
  {
    "label": "現在のファイルをPythonで実行",
    "command": "python",
    "args": ["$ZED_FILE"]
  }
]
```

`label`と`command`が必須のキーです。よく使うオプションを整理します：

| キー                    | 内容                                                                        |
| ----------------------- | --------------------------------------------------------------------------- |
| `use_new_terminal`      | 新しいターミナルタブで実行する（デフォルトは`false`）                       |
| `allow_concurrent_runs` | 前回の実行中でも重複起動を許可する                                          |
| `reveal`                | 実行時にターミナルパネルをどう表示するか（`always` / `no_focus` / `never`） |
| `hide`                  | 終了後にパネルを隠すタイミング（`never` / `always` / `on_success`）         |
| `save`                  | 実行前に保存するファイル（`all` / `current` / `none`）                      |

### タスク変数

コマンドや引数の中で、現在の編集状態に応じた値を変数として参照できます：

| 変数                 | 内容                       |
| -------------------- | -------------------------- |
| `$ZED_FILE`          | 現在のファイルの絶対パス   |
| `$ZED_FILENAME`      | ファイル名（パスなし）     |
| `$ZED_STEM`          | 拡張子を除いたファイル名   |
| `$ZED_RELATIVE_FILE` | ワークツリーからの相対パス |
| `$ZED_ROW`           | カーソルの行番号           |
| `$ZED_COLUMN`        | カーソルの列番号           |
| `$ZED_SELECTED_TEXT` | 選択中のテキスト           |
| `$ZED_SYMBOL`        | カーソル位置のシンボル名   |
| `$ZED_WORKTREE_ROOT` | ワークツリーのルートパス   |
| `$ZED_LANGUAGE`      | 現在のファイルの言語       |

これらを組み合わせると、「カーソルがある行のテストケースだけを実行する」「選択したテキストを引数としてスクリプトに渡す」といった細かい制御も記述できます。

### タスクの実行と再実行

`task: spawn`を実行すると定義済みタスクの一覧がモーダルで表示されます。名前の一部を入力して絞り込めるので、タスク数が増えても素早く起動できます。直前に実行したタスクを繰り返すには`task: rerun`を使います。テストを書いては`task: rerun`で都度走らせるサイクルが手軽に回ります。

![task: spawn のタスク一覧モーダル。tasks.jsonで定義したタスクとpackage.jsonのスクリプトが並ぶ](/images/zed-book/ch6-task-spawn.png)
_コマンドパレットで「task: spawn」を実行すると定義済みタスクの一覧が開く。package.json のスクリプトも自動検出される_

`.vscode/tasks.json`が存在するプロジェクトでは、その定義が自動的にインポートされます。VS Code環境からの移行でタスク設定を書き直す必要はありません。

## 組み込みターミナル

Zedには本格的なターミナルエミュレータが内蔵されています。`` ctrl-`  ``でパネルとしてトグル表示でき、通常のエディタタブとして開くこともできます。

複数のターミナルを並行して使いたい場合は、ターミナルペイン内で`cmd-d`を押してペインを分割します。一方でサーバーを動かしながらもう一方でコマンドを試す、といった使い方が1つのウィンドウ内で完結します。

**Pythonの仮想環境自動検出**も実用的な機能です。venvやPoetryなどの仮想環境がプロジェクトに含まれていれば、ターミナルを開いた時点で自動的に有効になります。毎回`source .venv/bin/activate`を打つ手間が省けます。

ターミナルの出力中のファイルパスは`cmd` を押しながらクリックでエディタ内に直接開けます。コンパイルエラーやスタックトレースに含まれるパスをそのままクリックして該当ファイルへ飛べるので、エラー確認の行き来が速くなります。

AIの手を借りたい場面では、ターミナル内で`ctrl-enter`を押すとインラインアシスタントが起動します。「このコマンドの使い方を教えて」「このオプションをどう書けばいいか」といった質問をその場でできます。

タスクの実行結果もターミナルパネルに表示されます。`cmd-alt-r`で直前のタスクを再実行できるので、エラーを見てコードを直してすぐ再実行する、というループがパネルから離れずに完結します。

## デバッガ

### DAPベースの設計

ZedのデバッガはDAP（Debug Adapter Protocol）を採用しています。DAPはMicrosoftが策定した標準プロトコルで、デバッガとエディタが言語非依存の形式で通信する仕組みです。DAPに対応したデバッグアダプターがあれば、言語固有の実装をエディタ本体に持たなくて済みます。

現在、Zedに組み込まれているアダプターはC、C++、Go、JavaScript、PHP、Python、Rust、TypeScriptの8言語です。Java、Ruby、Swiftはそれぞれの対応拡張機能を追加することで使えます。

### ブレークポイントを設定する

ブレークポイントは行番号の左側をクリックするだけで設定できます。設定済みのブレークポイントを右クリックすると、より細かい制御が可能になります：

- **ログポイント**：プログラムを止めずにメッセージをコンソールに出力する
- **条件付きブレークポイント**：指定した条件式が真のときだけ停止する
- **ヒットカウント**：指定した回数だけ通過した後に停止する
- **無効化**：ブレークポイントを残したまま一時的にスキップする

ループの中で特定の条件のときだけ止まりたい、重い処理の何回目を確認したい、といった場面でこれらのオプションは役立ちます。

### debug.jsonで起動設定を管理する

デバッグの起動設定はプロジェクトの`.zed/debug.json`にJSON配列として記述します：

```jsonc
// .zed/debug.json
[
  {
    "label": "Pythonスクリプトを起動",
    "adapter": "Python",
    "request": "launch",
    "program": "$ZED_FILE",
    "cwd": "$ZED_WORKTREE_ROOT"
  },
  {
    "label": "Goサーバーにアタッチ",
    "adapter": "Go",
    "request": "attach",
    "processId": "${command:pickProcess}"
  }
]
```

`adapter`と`label`が必須のキーです。`request`には`launch`（新規プロセスとして起動）または`attach`（実行中のプロセスにアタッチ）を指定します。`cwd`にはタスク変数と同様に`$ZED_WORKTREE_ROOT`なども使えます。グローバルな設定は`~/Library/Application Support/Zed/debug.json`に置くこともできます。

デバッグセッションを始めるには、コマンドパレットから`debugger: start`を実行するか、`F4`キーを押します。定義済み設定の一覧がモーダルで表示され、選んだ設定でデバッグが始まります。

`.vscode/launch.json`が存在するプロジェクトでは、その設定も自動的に読み込まれます。VS Codeからの移行でデバッグ設定を書き直す必要はありません。

## REPLとJupyterサポート

データ分析や実験的なコードを対話的に実行したい場面では、ZedにはJupyterカーネルを使った組み込みREPLがあります。現在対応しているカーネルはPython（ipykernel）、TypeScript（Deno）、R（Ark/Xeus）、Julia、Scalaです。

Pythonのスクリプトであれば、`# %%`という区切りコメントでコードをセルに分割し、`repl: run`コマンドでセルごとに実行できます。実行結果はコードの直下に表示されます。Notebookファイルを別ツールで開かずに、通常のPythonスクリプトをインタラクティブに動かせる点が実用的です。

REPLの詳細な設定（カーネルの選択方法やリモートサーバーへの接続など）については公式ドキュメントのREPLページを参照してください。
