---
title: "エディタ機能を使いこなす"
---

エディタを日々使いこなすうえで、ファイルを素早く開き、コードを横断的に検索し、複数の変更を一気に加えるという一連の作業は、開発時間の大部分を占めます。Zed はこれらをそれぞれ独立した機能として提供しているわけではなく、バッファ、ペイン、マルチバッファという一貫したモデルのうえに積み重ねています。個々の操作を覚えることも大切ですが、このモデルを理解すると、Zed を使う際に地に足のついた感覚が生まれます。

この章では、画面の構成から始め、ファイルの探し方、コードの検索、マルチカーソル、そしてこの章の核心であるマルチバッファ、コードナビゲーション、Vim モードを順に見ていきます。AI エージェントによる開発が中心の本書であっても、エージェントが生成したコードを検証したり手を加えたりするのは結局のところ人間です。エディタ機能を使いこなせると、AI との協業がより滑らかになります。

言語サーバーを使った診断やフォーマット、タスク実行は第 6 章で、Git 操作は第 7 章で、キーバインドのカスタマイズは第 8 章でそれぞれ扱います。

## バッファ・ペイン・タブ

Zed の画面を構成する概念は、バッファ、ペイン、タブの三層構造で理解できます。

**バッファ**は、ディスク上のファイルをメモリに読み込んだ実体です。ファイルを開くとひとつのバッファが生まれ、編集はバッファ上で行われます。ファイルを保存するまでディスクの内容は変わらず、編集中の変更はすべてバッファに留まります。

**ペイン**は、バッファを表示する窓枠です。画面上のひとつの編集エリアがペインに相当します。**タブ**は、ひとつのペイン内で複数のバッファを切り替えて表示するためのもので、ブラウザのタブと同じ概念です。Zed は起動直後はペインがひとつですが、分割することで複数のバッファを画面上に同時に表示できます。

### 画面を分割する

`cmd-k` に続いて方向キーを押すと、現在のペインを任意の方向に分割できます。

| 操作       | キー                |
| ---------- | ------------------- |
| 上下に分割 | `cmd-k` → `↑` / `↓` |
| 左右に分割 | `cmd-k` → `←` / `→` |

分割後は、タブを別のペインにドラッグして移動することもできます。あるファイルで実装を確認しながら別のファイルを書く、テストと本体を並べて確認するといった作業が、直感的な操作でできます。ペインが不要になったときは、最後のタブを閉じると自動的にペインも閉じます。

![左右2ペインに分割し、左にmain.ts、右にformatter.tsを並べた状態](/images/zed-book/ch5-split-panes.png)
_cmd-k → → で左右分割。呼び出し側と定義側を並べて確認できる_

## ファイルを開く

### ファイルファインダー

`cmd-p` でファイルファインダーを開きます。キーを入力するたびにインクリメンタルにファイルが絞り込まれ、ファイル名やパスの一部を入力して素早く目的のファイルに飛べます。あいまいマッチに対応しているので、`src/utils/formatter.ts` を開きたければ `ufmt` のように打鍵数を大きく減らすことができます。

プロジェクトパネルと違いマウスなしで操作できるため、キーボード中心の作業スタイルと相性の良い機能です。Zed でファイルを開くなら、たいていこのコマンドで事足ります。

![ファイルファインダーに「ufmt」と入力し、src/utils/formatter.tsがあいまいマッチで絞り込まれた状態](/images/zed-book/ch5-file-finder.png)
_cmd-p で開くファイルファインダー。「ufmt」の4文字で utils/formatter.ts に到達できる_

### プロジェクトパネル

`cmd-shift-e` でプロジェクトパネルを開閉します。ファイルツリーを階層で表示し、矢印キーでディレクトリを展開・折りたたみながらファイルを探せます。

プロジェクトパネルの細かい挙動として知っておきたいのが、スペースキーによるプレビューです。エントリを選択してスペースを押すと、**一時タブ**としてファイルが開きます。ファイルの内容を素早く確認したいだけで、タブに常駐させたくない場合に便利です。一時タブは次にファイルを開くと置き換えられます。編集を開始するか Enter キーを押すか、あるいはダブルクリックすると通常のタブに昇格します。

デフォルトでは、エディタで編集中のファイルがプロジェクトパネル上で自動的にハイライトされます。深い階層のファイルを開いている際に、ファイルツリー上の位置を把握するのに役立ちます。

### タブスイッチャーと最近のプロジェクト

`ctrl-tab` を押すと、開いているタブが最近使用順に一覧表示されます。`Ctrl` を押したまま `Tab` を繰り返すことで一覧を上から辿れます。`ctrl-shift-tab` で逆順に辿ることもできます。

複数のプロジェクトを行き来する場合は `alt-cmd-o` が便利です。最近開いたプロジェクトの一覧が表示され、選択すると切り替えられます。Zed では複数のプロジェクトを同時に開くこともでき、それぞれが独立したファイルツリーと検索スコープを持ちます。

## アウトラインとシンボル検索

### バッファ内のアウトライン

`cmd-shift-o` を押すと、現在のファイルのシンボル一覧（関数やクラス、変数など）がポップアップで表示されます。インクリメンタル検索で絞り込みながら目的のシンボルに移動できます。ファイルの全体構造を俯瞰したいとき、あるいは「あの関数はどこに定義したか」を素早く確認したいときに使います。1,000 行を超えるようなファイルでも、このコマンドがあれば迷子になりにくくなります。

### アウトラインパネル

`cmd-shift-b` でアウトラインパネルを開きます。こちらはポップアップではなく、サイドバーに常駐するパネルです。コードを書きながら横目でファイルの構造を把握したいとき、あるいは後述のマルチバッファで大量の検索結果を俯瞰するときに特に力を発揮します。

### プロジェクト全体のシンボル検索

`cmd-t` を使うと、プロジェクト全体のシンボルを横断的に検索できます。こちらはプロジェクト全体が対象です。「このインターフェースを実装しているクラスはどこか」「その名前の型定義はどこにあるか」を調べるときに使えます。

## プロジェクト全体検索

`cmd-shift-f` でプロジェクト全体のテキスト検索を開きます。単純な文字列検索はもちろん、検索パネル内のトグルで正規表現モードに切り替えることもできます。

ファイルを限定したい場合は、検索パネル内の「含めるファイル」「除外するファイル」フィールドを使います。glob パターンで記述し、例えば `src/**/*.ts` と入力すれば TypeScript ファイルのみが対象になります。`**/node_modules/**` を除外パターンに指定すれば依存関係を検索対象から外せます。広大なモノレポで作業する場合、検索時間が短くなり結果も見通しやすくなります。

検索パネルには置換フィールドもあります。検索語と置換後の文字列を入力して「すべて置換」を実行すると、プロジェクト全体の一括置換を行えます。ただし、マルチバッファを使った置換との違いを意識しておくと良いです。置換パネルは高速で手軽ですが、変更内容をひとつひとつ確認しながら進めたい場合は、マルチバッファに出してから手作業で確認しつつ置き換えるほうが安全です。

検索結果は後述の**マルチバッファ**として表示され、そのまま編集できます。「検索してその場で編集」という流れは Zed の核心体験のひとつで、次節で詳しく扱います。

## マルチカーソル

マルチカーソルは、コードの複数の箇所に同時にカーソルを置き、まとめて編集する機能です。変数名の変更や繰り返しパターンの編集など、同じ操作を複数の場所に適用したいときに使います。

最もよく使うのは `cmd-d` です。テキストを選択した状態で押すと、同じ文字列の次の出現箇所を追加で選択します。さらに押せば次々と選択範囲が増え、`cmd-shift-l` ですべての一致箇所を一度に選択できます。

行単位でカーソルを増やしたい場合は `cmd-alt-up` で上の行に、`cmd-alt-down` で下の行にカーソルを追加します。`alt` を押しながらクリックでも任意の位置にカーソルを追加できます。

| 操作                     | キー                       |
| ------------------------ | -------------------------- |
| 次の一致を追加選択       | `cmd-d`                    |
| すべての一致を選択       | `cmd-shift-l`              |
| 上の行にカーソル追加     | `cmd-alt-up`               |
| 下の行にカーソル追加     | `cmd-alt-down`             |
| 任意の位置にカーソル追加 | `alt` を押しながらクリック |

マルチカーソルの真の力は、後述のマルチバッファと組み合わせたときに発揮されます。1 ファイル内の複数行への同時編集に留まらず、プロジェクト全体に散らばった箇所をまとめて書き換えられます。

## マルチバッファ

マルチバッファは、Zed のエディタ機能のなかで最も独自性の高い機能です。複数のファイルの断片を 1 つのバッファに集め、そこで直接編集できます。プロジェクト全体にまたがる変更を、ファイルを 1 つずつ開いて回ることなく行えます。

他のエディタでもプロジェクト全体検索の結果を閲覧することはできますが、それはあくまでも読み取り専用のプレビューです。目的のファイルが分かったら改めてそのファイルを開いて編集する、という手順を踏みます。Zed のマルチバッファはその前提を変えます。表示された検索結果そのものが編集可能なバッファであり、カーソルを置いて書き換えれば、対応するファイルに即座に反映されます。この設計のおかげで、Zed らしいワークフローが生まれます。

### マルチバッファが生まれる場面

マルチバッファはいくつかの操作の結果として自動的に作られます。

**プロジェクト検索（`cmd-shift-f`）の結果**がその代表例です。検索を実行すると、一致した行の前後数行を含む抜粋が各ファイルからひとつのバッファに集まります。結果はファイルごとにグループ化され、それぞれのグループにはファイルパスのヘッダが付きます。その場で内容を読むだけでなく、カーソルを移動して編集を加えることができます。

![プロジェクト検索結果のマルチバッファ。main.tsとformatter.tsのヘッダ付き抜粋が1つのバッファに並び、一致箇所がハイライトされている](/images/zed-book/ch5-search-multibuffer.png)
_cmd-shift-f の検索結果はマルチバッファとして展開される。表示されているコードはそのまま編集可能_

**参照の検索**（`alt-shift-f12`）も同様です。あるシンボルへの参照が複数ファイルにまたがる場合、すべての参照がマルチバッファに集約されます。どのファイルのどの文脈で使われているかを一覧で確認しながら、必要に応じて変更を加えられます。

**定義へのジャンプ**（`F12`）も、定義が複数存在する場合はマルチバッファに展開されます。インターフェースと複数の実装が別ファイルに散らばっている場合などが典型です。

### マルチバッファで編集する

マルチバッファの最大の特長は、**通常のバッファとまったく同じように編集できる**ことです。カーソルを動かしてテキストを書き換えれば、それが対応するファイルに即座に反映されます。変更は複数ファイルにまたがっていても構いません。`cmd-s` で、マルチバッファ内で変更したすべてのファイルをまとめて保存できます。

ここにマルチカーソルを組み合わせると、プロジェクト全体への一括変更を効率的に行えます。例として、ある設定キーの文字列リテラルを別の名前に変更したいとします。`cmd-shift-f` で旧名称を検索すると、すべての出現箇所がマルチバッファに並びます。`cmd-shift-l` で一覧内のすべての一致を選択し、新しい名前を入力すれば、一度のキー入力で全件が書き換わります。`cmd-s` で保存すれば完了です。従来のエディタなら「検索」「ファイルごとに開いて編集」「保存」を繰り返す必要があった作業が、数ステップに集約されます。

### アウトラインパネルとの組み合わせ

検索結果が多い場合、マルチバッファ内のどこに何があるか把握しにくくなることがあります。そのときに役立つのがアウトラインパネル（`cmd-shift-b`）です。マルチバッファを開いた状態でアウトラインパネルを表示すると、バッファ内に現れているファイル名やシンボルが一覧で表示され、クリックで直接その箇所に飛べます。膨大な参照一覧を持つシンボルを扱うときに、このふたつの組み合わせが便利です。

## コードナビゲーション

言語サーバーに接続したプロジェクトでは、定義や参照を辿ってコードの構造を横断できます。ファイルをまたいだジャンプも、戻るキー一発で元の位置に戻れるため、迷子になりにくい作業感があります。言語サーバーの設定については第 6 章で詳しく扱いますが、ここでは操作の方法を見ておきます。

### 定義へジャンプする

`F12`、または `cmd` を押しながらクリック でカーソル下のシンボルの定義にジャンプします。関数呼び出しの上で実行すれば、その関数が定義されたファイルの該当行に移動します。

`alt-f12` を使うと、現在のペインを分割した新しいペインに定義を表示します。元のファイルを閉じずに定義を確認したいときに便利で、確認したら `cmd-w` でそのペインを閉じれば元の作業に戻れます。

### 参照を検索する

`alt-shift-f12` で、現在のシンボルへのすべての参照をマルチバッファとして開きます。前節で述べたとおり、この結果はそのまま編集できます。シンボルをリネームする際、まず参照一覧をマルチバッファに出してからマルチカーソルで一括置換するのが実践的な流れです。

### 戻る・進む

`ctrl--` で直前の位置に戻り、`ctrl-shift--` で次の位置に進みます。定義にジャンプした後、元の場所に戻りたいときによく使います。ブラウザの「戻る」ボタンに相当する感覚で、定義を辿りながら深い階層に潜っても、同じキーで段階的に元の位置に戻ってこられます。

| 操作                       | キー                               |
| -------------------------- | ---------------------------------- |
| 定義へジャンプ             | `F12` / `cmd` を押しながらクリック |
| 定義を分割表示             | `alt-f12`                          |
| 参照をマルチバッファで開く | `alt-shift-f12`                    |
| 前の位置に戻る             | `ctrl--`                           |
| 次の位置に進む             | `ctrl-shift--`                     |

## Vim モード

Zed には Vim モードが内蔵されています。Vim に慣れた開発者なら、大きく操作を変えずに乗り換えられます。

### 有効にする

コマンドパレット（`cmd-shift-p`）を開き、`workspace: toggle vim mode` を実行します。ウェルカム画面でチェックボックスをオンにする方法もあります。いずれの方法でも、ユーザー設定に `"vim_mode": true` が書き込まれます。

### 基本的な動作

Vim モードを有効にすると、エディタは Normal モードで起動します。`i` で Insert モード、`v` で Visual モード、`Esc` で Normal モードに戻るという基本的な操作が使えます。`:w` でファイルを保存し、`/` で検索を開始するといった Vim のコマンドラインも機能します。プロジェクト検索の `cmd-shift-f` に相当するコマンドは Vim モードでは `g/` と入力します。

Zed の Vim 実装はいくつかの点で標準の Vim と意図的に異なります。Visual Block 選択は Zed のマルチカーソルで実現されており、Vim の矩形選択とは挙動が異なります。正規表現のキャプチャグループは `\1` ではなく `$1` を使い、グループの記法も `\(` ではなく `(` です。こうした差異は、Zed の内部実装との兼ね合いから来る意図的な選択です。

Vim モードの詳細な設定やキーバインドのカスタマイズについては、第 8 章で改めて扱います。

---

この章で扱った機能は一度に全部覚える必要はありません。まずファイルファインダー（`cmd-p`）とプロジェクト検索（`cmd-shift-f`）を日常に取り入れ、次に `cmd-d` によるマルチカーソルを使い始め、プロジェクト全体の変更が必要になったときにマルチバッファの威力を体感してみてください。それぞれの機能を実際の作業のなかで使いながら身体に覚えさせていくのが、Zed を使いこなす近道です。
