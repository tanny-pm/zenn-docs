title: "Zedをはじめる"
---

新しいエディタとの付き合いは、セットアップから始まります。ここで少し丁寧に時間をかけておくと、その後の学習がずっとスムーズになります。この章では、MacにZedをインストールするところから出発し、初回起動のオンボーディング、コマンドラインツールのセットアップ、設定ファイルの流儀、見た目の初期調整、そして日々の開発で欠かせない基本操作の習得まで、順を追って進めます。

インストール自体は数分で終わります。しかしその後に初期設定が続きます。base keymapをどれにするか、設定はどのファイルに書くのか、よく使う操作をどのキーで呼び出すのか。これらを早い段階でつかんでおくかどうかで、その後の使い心地が変わってきます。第3章以降で扱うAI機能も、この章で整えた土台の上に乗っています。急いで先へ進みたいところですが、まずここをしっかり固めていきましょう。

## Zedをインストールする

ZedをMacにインストールする方法は大きく2つあります。公式サイト（zed.dev/download）からdmgファイルをダウンロードしてアプリケーションフォルダにドラッグする方法と、Homebrewを使う方法です。

```bash
brew install --cask zed
```

本書ではHomebrewを推奨します。インストールが一行で済むというだけでなく、`brew upgrade --cask zed`でアップデートも管理できるため、ほかの開発ツールとバージョン管理の方法を統一できます。Macで開発をしているなら、すでにHomebrewが入っている場合がほとんどでしょう。

dmgファイルから手動でインストールする方法が向いているのは、Homebrewを使っていない環境や、特定バージョンを固定して使いたい場面です。どちらの方法でも最終的に得られるアプリケーションは同じで、機能に差はありません。

Zedにはプレビュー版もあります。新機能が先行して入る開発版で、Homebrewなら`brew install --cask zed@preview`でインストールできます。安定版と同時に使うこともできますが、本書の説明はすべて安定版を前提にしています。まず安定版での操作に慣れてから、興味があれば試してみてください。

インストールが完了したら、LaunchpadまたはFinderのアプリケーションフォルダからZedを起動してみましょう。

## はじめての起動とオンボーディング

Zedを初めて起動すると、いくつかの初期設定を選ぶオンボーディング画面が表示されます。選択肢はどれもあとから変更できますが、ここで少し丁寧に選んでおくと、使い始めが楽になります。

![Zedの初回起動時に表示されるオンボーディング画面。テーマとbase keymap、AIエージェントのセットアップ項目が並ぶ](/images/zed-book/ch2-onboarding.png)
_初回起動時のオンボーディング画面。ここで選んだ設定はあとから変更できる_

最初に選ぶのが**base keymap**です。Zed全体のキーバインドの基本的な割り当てを決める設定で、VS CodeやSublime Text、Atomなど複数の選択肢が用意されています。VS Codeをそれまで使っていたなら、VS Codeキーマップを選んでおくのが無難です。コマンドパレットやファイル検索といった基本操作が、慣れたキーの組み合わせで動く状態から始められます。

次はテーマです。Zedには組み込みテーマが複数あり、ライトとダークの両方が揃っています。あとから何度でも変えられるので、まず目に良さそうなものを選んでおけば十分です。変更方法はこの章の「見た目の初期調整」で改めて説明します。

最後にGitHubアカウントでのサインインを求められます。Zedのコラボレーション機能と、組み込みのAI機能を使うために必要なステップです。本書が第3章以降で扱うAIエージェント機能も、このサインインが前提になります。GitHubのアカウントがあれば数クリックで完了するので、ここで済ませてしまいましょう。

オンボーディングが終わると、ウェルカムページが表示されます。ここからフォルダを開いたり、リポジトリをクローンしたりできます。すぐにコードを書き始めたいところですが、その前にCLIのセットアップを済ませておきましょう。

![Zedのウェルカムページ。プロジェクトを開く、リポジトリをクローンするなどの操作が並ぶ](/images/zed-book/ch2-welcome.png)
_起動直後のウェルカムページ。コマンドパレットで「zed: show welcome」を実行すると再表示できる_

### 自動アップデートについて

Zedは起動時に自動で更新を確認し、新しいバージョンがあればバックグラウンドでダウンロードします。次回起動時に新バージョンが適用される仕組みなので、ユーザーが特に何かをする必要はありません。Homebrewでインストールした場合も、同じ仕組みで自動更新されます。ほぼ意識しないまま、手元には常に最新の安定版がある状態を保てます。

## CLIコマンドをセットアップする

GUIからZedを起動するのもいいのですが、ターミナルで`zed .`と打ってプロジェクトを開ける状態にしておくと、日々の開発がぐっと快適になります。Zedはそのためのコマンドラインツールを用意していますが、インストール直後の状態では有効になっていません。

CLIをインストールするには、コマンドパレット（`cmd-shift-p`）を開いて`cli`と入力します。`cli: install cli binary`というアクションが候補に出てくるので、Enterで実行します。これで`/usr/local/bin/zed`へのシンボリックリンクが作成され、ターミナルから`zed`コマンドが使えるようになります。macOSのメニューバーからZed→Install CLIを選んでも同じことができます。

![コマンドパレットに「cli」と入力した状態。「cli: install cli binary」が候補として表示される](/images/zed-book/ch2-command-palette-cli.png)
_コマンドパレットで「cli」と検索するとCLIのインストールコマンドが現れる_

インストールが済んだら、ターミナルを新しく開いて試してみましょう。

```bash
# 現在のディレクトリをプロジェクトとして開く
zed .

# 特定のファイルを開く
zed src/main.py

# ファイルの特定行へジャンプして開く
zed src/main.py:42

# 新しいウィンドウで開く
zed -n ~/projects/my-app

# 複数のファイルを同時に開く
zed file1.ts file2.ts
```

`zed .`が手になじむと、ターミナルで`cd`してプロジェクトのルートへ移動し、`zed .`を打つというリズムが自然になってきます。プロジェクトを切り替えるたびにGUIのダイアログを操作する必要がなくなるだけで、作業の流れがずいぶん変わります。

もう1つ設定しておくと便利なのが、デフォルトエディタの環境変数です。`.zshrc`などシェルの設定ファイルに次の行を追加しておきます。

```bash
export EDITOR="zed --wait"
```

これでGitのコミットメッセージ編集など、エディタを求めるコマンドの実行時にZedが起動するようになります。`--wait`オプションを付けるのは、Zedでファイルを閉じるまで呼び出し元のプロセスを待機させるためです。このオプションがないと、Gitはファイルが閉じられる前にコミット処理を進めてしまいます。

## 設定ファイルの流儀

Zedの設定はJSONファイルで管理します。GUIの設定エディタも用意されていますが、そこで変えた内容も最終的には同じJSONファイルに書き込まれます。テキストファイルを直接編集するのが基本にあり、GUIはその入口のひとつという位置づけです。設定UIに慣れていると最初は少し面食らうかもしれませんが、テキストで管理できるおかげで、設定をGitリポジトリで追跡したり、別のマシンへそのまま持ち運んだりするのが簡単になります。

主な設定ファイルは2つあります。

`~/.config/zed/settings.json`はZed全体の設定を記述するファイルです。フォント、テーマ、言語ごとの設定、AIモデルの選択、フォーマッターの挙動など、ほぼすべての設定がここに集約されます。プロジェクトごとに設定を上書きしたい場合は、プロジェクトのルートに`.zed/settings.json`を置くこともできます。チーム開発でエディタの設定を共有するのに便利です。

`~/.config/zed/keymap.json`はキーバインドのカスタマイズに使います。デフォルトのキーバインドを変更したり、新しい操作を追加したりする場合にここへ書きます。カスタマイズの詳細は第8章で扱うので、今は場所と役割だけ覚えておけば十分です。

### settings.jsonを開く

settings.jsonを開くには、コマンドパレット（`cmd-shift-p`）から`open settings`と入力し、`zed: open settings`を選びます。

JSONを直接書くのに抵抗があるうちは、GUIの設定エディタから始めても構いません。`cmd-,`を押すと、専用のウィンドウで設定エディタが開きます。左側にGeneral、Appearance、Editor、AIといったカテゴリが並び、各項目はトグルやドロップダウンで操作できます。上部の検索ボックスに語句を入れれば、目的の設定を横断的に探せます。

![Zedの設定エディタ。左にカテゴリ一覧、上部に検索ボックス、各項目がトグルやドロップダウンで並ぶGUI画面](/images/zed-book/ch2-settings-editor.png)
_cmd-, で開く設定エディタ。トグルやドロップダウンで設定を変更でき、各項目には「Edit in settings.json」ボタンも用意されている_

つまりZedは、JSONの直接編集とGUIの設定エディタのどちらも使えます。GUIで変えた内容も最終的にはsettings.jsonへ書き込まれるので、両者は同じ設定を別の入口から触っているにすぎません。設定エディタの各項目には「Edit in settings.json」ボタンがあり、GUIで場所を探してからJSONへ飛ぶ、という行き来もできます。何がどこにあるかを掴むまではGUIを起点にし、慣れてきたらJSONを直接編集するほうが速くなっていくはずです。

base keymapをオンボーディング後に変更したい場合は、settings.jsonに次のように書きます。

```jsonc
{
  "base_keymap": "VSCode"
}
```

### keymap.jsonを開く

キーマップファイルを開くには、コマンドパレットから`keymap`と入力して出てくるアクションを使います。あるいは`cmd-k cmd-s`でキーマップエディタを開くと、現在定義されているキーバインドの一覧を確認しながら編集できます。

## 見た目の初期調整

毎日向き合うエディタの見た目は、早めに決めておくに越したことはありません。とはいえ、テーマ探しに午後を溶かしてしまっては本末転倒です。ここではフォントとテーマだけ、さっと整えてしまいましょう。

### フォントを設定する

エディタ本文のフォントは`buffer_font_family`で指定します。`buffer_font_size`でサイズも変えられます。

```jsonc
{
  "buffer_font_family": ".ZedMono",
  "buffer_font_size": 14
}
```

Zedは`.ZedMono`というモノスペースフォントを同梱しています（実体はLilexというオープンソースフォントです）。デフォルトのままでも十分に読みやすいので、まずはそのまま使ってみて、気になったら変えるという判断で構いません。Macにインストール済みのフォントなら何でも指定できるので、普段使っているプログラミングフォントがあれば、そちらを指定してください。

### テーマを変える

テーマの変更は`cmd-k cmd-t`で開くテーマセレクタから行います。一覧でテーマを選ぶと即座に画面へ反映されるので、見た目を確かめながら決められます。決まったらEnterで確定します。

![テーマセレクタでOne Darkをハイライトし、画面全体がダークテーマでプレビューされている状態](/images/zed-book/ch2-theme-selector.png)
_テーマセレクタ（cmd-k cmd-t）。候補に合わせるだけで画面全体へ即座にプレビューが反映される_

macOSのダークモードとライトモードに合わせて自動で切り替える設定もあります。settings.jsonに次のように書きます。

```jsonc
{
  "theme": {
    "mode": "system",
    "light": "One Light",
    "dark": "One Dark"
  }
}
```

`mode`を`"system"`にすると、OSの外観設定に連動してテーマが切り替わります。固定したい場合は`"light"`または`"dark"`を指定します。サードパーティのテーマを追加する方法は第8章で扱います。

## 最初の10分の操作

設定が一通り整ったら、Zedの基本操作を手になじませていきます。覚えるのはいくつかのキーの組み合わせだけです。ここでは最初の10分で使う操作に絞って紹介します。

### コマンドパレット

`cmd-shift-p`で開く**コマンドパレット**は、Zedのあらゆる操作の入口です。設定を開く、テーマを変える、AI機能を呼び出す、拡張機能を管理する。こうした操作がすべてここから始まります。アクション名の一部を打ち込むだけで候補が絞り込まれ、キーボードから手を離さずに目的の操作へたどり着けます。

Zedでこの操作はどうやるんだろう、と思ったときは、まずコマンドパレットに打ち込んでみてください。ドキュメントを探し回るより、たいてい早く答えが見つかります。最初のうちはコマンドパレットに頼り、頻繁に使う操作から少しずつキーバインドを覚えていく。このペースで進めると無理がありません。

### ファイルファインダー

`cmd-p`で開く**ファイルファインダー**は、プロジェクト内のファイルをあいまい検索で素早く開く機能です。ファイル名の一部を入力するだけで候補が絞り込まれ、Enterで開きます。ファイル数が多いプロジェクトでも、ファイルツリーをマウスでたどる必要がなくなります。名前の一部さえ覚えていれば、2〜3文字の入力で目的のファイルに届くことも珍しくありません。

### プロジェクトを開く

CLIのセットアップが済んでいれば、ターミナルでプロジェクトのルートに移動して`zed .`と打つのが一番手軽です。GUI操作が好みなら`cmd-o`でフォルダ選択ダイアログを開けます。

Zedは終了時のウィンドウとプロジェクトの状態を記憶していて、次回起動時に復元します。作業の途中で終了しても、開き直せば続きから始められます。

ウィンドウ左端のプロジェクトパネルにはファイルツリーが表示されます。コマンドパレットで`project panel`と検索すれば、表示と非表示を切り替えるアクションが見つかります。

### 組み込みターミナル

`` ctrl-` ``でZedに内蔵されたターミナルを開けます。エディタとターミナルが同じウィンドウにあるので、コードを書きながらコマンドを実行する流れが途切れません。外部のターミナルアプリとの行き来が減るだけで、集中は保ちやすくなります。もう一度同じキーを押せば非表示になります。

### プロジェクト内の検索

`cmd-shift-f`でプロジェクト全体を横断してテキストを検索できます。正規表現にも対応しています。関数名やクラス名といったシンボルを探したい場合は、`cmd-shift-o`で現在のファイル内のシンボル一覧から選べます。

この章で登場したキーバインドをまとめておきます。

| 操作                       | キーバインド |
| -------------------------- | ------------ |
| コマンドパレット           | cmd-shift-p  |
| ファイルファインダー       | cmd-p        |
| プロジェクトを開く         | cmd-o        |
| 設定エディタ               | cmd-,        |
| テーマセレクタ             | cmd-k cmd-t  |
| キーマップエディタ         | cmd-k cmd-s  |
| ターミナルの表示と非表示   | ctrl-\`      |
| プロジェクト内テキスト検索 | cmd-shift-f  |
| シンボル検索               | cmd-shift-o  |
| Agent Panel                | cmd-shift-a  |

## 次の章へ

この章ではZedのインストールから基本操作まで、一通りのセットアップを済ませました。Homebrewでインストールし、オンボーディングでキーマップとテーマを選び、GitHubアカウントでサインインしました。CLIを使えるようにして、設定ファイルの場所と開き方を把握し、コマンドパレットとファイルファインダーの感触もつかみました。

ここからが、本書がZedを勧める理由の中心です。

第3章では**Agent Panel**（`cmd-shift-a`）を使ったAIエージェント開発を扱います。コードの生成や修正、リファクタリングをAIに委ねながら、自分はより高い視点で開発を進める。そのスタイルをZedがどう実現しているかを見ていきます。GitHubアカウントでのサインインが済んでいれば、次の章へ進む準備はもう整っています。
